    Generalización o composición: elegir bien

    Cuándo usar herencia («es-un») y cuándo composición («tiene-un»).

    Módulo
    Relaciones entre clases
    Lección
    17 de 33
    Lectura
    6 min
    Fuente
    UF2404 · UD4 · 4.2

    Ideas clave

    • Generalización/especialización = herencia («es-un»).
    • Composición/agregación = «tiene-un».
    • Regla práctica: prefiere composición si dudas.
    En esta lección
    • Dos preguntas, dos relaciones
    • Mal y bien
    • Composición sobre herencia
    • Práctica
    • Autoevaluación

    Dos preguntas, dos relaciones#

    Pregúntate: ¿A es un B? Entonces hay generalización/especialización y puedes usar herencia. ¿A tiene un B? Entonces hay composición o agregación y A guarda una referencia a B.

    Mal y bien#

    // Mal: un Coche NO es un Motor
class Coche extends Motor { }

// Bien: un Coche TIENE un Motor
class Coche {
    private Motor motor;
}

    Composición sobre herencia#

    La herencia acopla fuertemente la subclase a la superclase. La composición permite cambiar piezas en tiempo de ejecución (un coche puede cambiar de motor) y es más flexible. Usa herencia para especializar tipos y composición para reutilizar comportamiento.

    Práctica

    Rediseña Pila extends ArrayList para usar composición. ¿Qué ventajas obtienes?

    Autoevaluación

    ¿Un Pedido «es un» Cliente o «tiene un» Cliente?

    Tiene un Cliente: es una relación de composición/asociación, no de herencia.

    La complejidad y el modelo de objetos

    Por qué el software es complejo y los siete elementos del modelo de objetos de Booch.

    Módulo
    Fundamentos y ciclo de desarrollo
    Lección
    4 de 33
    Lectura
    8 min
    Fuente
    Booch · cap. 1 y 2

    Ideas clave

    • El software es complejo por naturaleza; la tarea es crear una ilusión de sencillez.
    • Se domina con descomposición, abstracción y jerarquía.
    • El modelo de objetos tiene 4 elementos mayores y 3 menores.
    En esta lección
    • Complejidad inherente
    • Elementos mayores

    Complejidad inherente#

    Según Booch, el software es complejo de forma innata: la complejidad del dominio del problema, la dificultad de gestionar el proceso de desarrollo, la flexibilidad del software y el comportamiento de sistemas discretos. La tarea del equipo es crear una ilusión de sencillez. Para ello usamos tres herramientas: descomposición, abstracción y jerarquía.

    Elementos mayores#

    • Abstracción: características esenciales de un objeto.
    • Encapsulamiento: separar la interfaz «contractual» de la implementación.
    • Modularidad: módulos cohesivos y débilmente acoplados.
    • Jerarquía: ordenación de abstracciones (herencia y agregación).

    Elementos menores#

    Tipos (imponer la clase de un objeto), concurrencia (varios hilos de control) y persistencia (que el objeto trascienda en el tiempo). Un modelo es orientado a objetos si incluye los cuatro mayores.

    Práctica

    Para un sistema de reservas de hotel, nombra una abstracción, un módulo y una jerarquía.

    Autoevaluación

    ¿Cuáles son los cuatro elementos mayores del modelo de objetos?

    Abstracción, encapsulamiento, modularidad y jerarquía.

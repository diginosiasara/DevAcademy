    Herencia y la regla «es-un»

    Derivar clases a partir de otras y comprobar si la herencia está bien planteada.

    Módulo
    Herencia
    Lección
    12 de 33
    Lectura
    8 min
    Fuente
    UF2404 · UD3 · 3.1

    Ideas clave

    • Una subclase hereda atributos y métodos de su superclase.
    • Solo hereda si se cumple «es-un».
    • Toda clase Java desciende de Object.
    En esta lección
    • Concepto
    • La regla «es-un»
    • La clase Object
    • Práctica
    • Autoevaluación

    Concepto#

    La herencia es el proceso de derivar una clase (derivada o subclase) de otra (base o superclase), de modo que la subclase puede usar los métodos de la base. Actúa de modo jerárquico: cada clase tiene una superclase y cero o más subclases, y la herencia transfiere atributos y métodos hacia abajo.

    La regla «es-un»#

    Un coche «es un» vehículo, así que Coche puede heredar de Vehiculo. Pero «una línea es un punto?»: no, así que Linea no debe heredar de Punto. Test: «A es-un B». Un pájaro es un animal; un perro es un mamífero; un pastel de fresas es un pastel.

    class Vehiculo {
    protected int velocidad;
    void acelerar(int d) { velocidad += d; }
}
class Coche extends Vehiculo {
    private int puertas = 4;
    void abrirMaletero() { /* ... */ }
}
Coche c = new Coche();
c.acelerar(20);   // método heredado

    La clase Object#

    En Java solo se hereda de una clase (herencia simple) y toda clase desciende de Object, que aporta equals(), hashCode(), toString(), getClass() y clone().

    Si la herencia «es-un» no se sostiene, usa composición (lección sobre relaciones entre clases).

    Práctica

    Escribe tres frases «A es-un B» correctas y una incorrecta para un sistema de empleados.

    Autoevaluación

    ¿Es buena idea que Cuadrado herede de Rectangulo?

    Suele ser un mal diseño: si cambias solo el ancho, el cuadrado deja de ser cuadrado. La subclase no puede sustituir a la superclase (principio de Liskov).

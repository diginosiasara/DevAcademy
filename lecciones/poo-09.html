    Encapsulación e interfaz

    Ocultar los detalles internos y exponer solo una interfaz estable.

    Módulo
    Objetos y clases
    Lección
    9 de 33
    Lectura
    7 min
    Fuente
    UF2404 · UD1 · 1.4.2 y UD2 · 2.1

    Ideas clave

    • La encapsulación oculta la implementación y expone una interfaz.
    • Los atributos deben ser privados y accederse mediante métodos.
    • Así se puede cambiar el interior sin romper a quien usa la clase.
    En esta lección
    • Dos vistas del objeto

    Dos vistas del objeto#

    Los atributos de un objeto deben estar ocultos al resto: no se accede directamente a ellos para consultarlos o modificarlos, sino mediante métodos. Esa separación entre la vista externa (interfaz) y la interna (implementación) es la encapsulación. Como la caja negra de un avión, el objeto guarda su información y solo se alcanza a través de su interfaz.

    Niveles de visibilidad en Java#

    Modificadores de acceso
    ModificadorQuién accede
    privateSolo la propia clase
    (por defecto)Clases del mismo paquete
    protectedMismo paquete y subclases
    publicCualquier clase
    public class Cuenta {
    private double saldo;
    public void ingresar(double c) {
        if (c <= 0) throw new IllegalArgumentException("Importe no válido");
        saldo += c;
    }
    public double getSaldo() { return saldo; }
}
    Beneficio: si mañana cambia cómo se calcula getSaldo(), el código que usa la clase no tiene que modificarse.

    Práctica

    Añade a Cuenta un método retirar() que impida dejar el saldo en negativo.

    Autoevaluación

    ¿Por qué el atributo saldo es privado?

    Para que solo se modifique mediante métodos que validan los datos.

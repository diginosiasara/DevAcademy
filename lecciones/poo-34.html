    Caso práctico: implementar el paradigma completo

    Un programa que reúne clases, sobrecarga, atributos, interfaz, composición, herencia, abstracción y polimorfismo.

    Módulo
    Implementación en Java
    Lección
    34 de 57
    Lectura
    12 min
    Fuente
    UF2404 · UD9 · 9.6 a 9.14

    Ideas clave

    • Una clase abstracta define lo común; las subclases, lo específico.
    • Una interfaz añade capacidades transversales.
    • El código que usa los objetos trabaja con el tipo general.
    En esta lección
    • Enunciado
    • Diseño
    • Implementación
    • Práctica

    Enunciado#

    Una empresa tiene empleados fijos y por horas. Todos cobran, pero de forma distinta. Algunos pueden dirigir proyectos. Queremos calcular la nómina total sin que el código dependa del tipo de empleado.

    Diseño#

    • Empleado (abstracta): atributos nombre y método abstracto pago().
    • Fijo y PorHoras heredan de Empleado (herencia + polimorfismo).
    • Dirigente (interfaz) para quien puede dirigir.
    • Empresa contiene una lista de empleados (composición).

    Implementación#

    import java.util.*;

abstract class Empleado {
    private final String nombre;
    protected Empleado(String nombre) { this.nombre = nombre; }
    public String getNombre() { return nombre; }
    public abstract double pago();
    @Override public String toString() { return nombre + ": " + pago(); }
}
interface Dirigente { String dirigir(); }

class Fijo extends Empleado implements Dirigente {
    private final double sueldo;
    Fijo(String n, double sueldo) { super(n); this.sueldo = sueldo; }
    public double pago() { return sueldo; }
    public String dirigir() { return getNombre() + " dirige el proyecto"; }
}
class PorHoras extends Empleado {
    private final int horas; private final double tarifa;
    PorHoras(String n, int horas, double tarifa) { super(n); this.horas = horas; this.tarifa = tarifa; }
    PorHoras(String n, int horas) { this(n, horas, 12.5); }   // sobrecarga de constructor
    public double pago() { return horas * tarifa; }
}

class Empresa {
    private final List<Empleado> plantilla = new ArrayList<>();   // composición
    void contratar(Empleado e) { plantilla.add(e); }
    double nomina() { double t = 0; for (Empleado e : plantilla) t += e.pago(); return t; }
}

public class Main {
    public static void main(String[] args) {
        Empresa e = new Empresa();
        Fijo ana = new Fijo("Ana", 2000);
        e.contratar(ana);
        e.contratar(new PorHoras("Luis", 80));
        System.out.println(e.nomina());   // 3000.0
        System.out.println(ana.dirigir());
    }
}
    Comprueba: si añades Becario, ¿tienes que cambiar Empresa.nomina()? No: ese es el valor del polimorfismo.

    Práctica

    Añade la clase Becario y la excepción SalarioInvalidoException cuando el pago sea negativo.

    Autoevaluación

    ¿Por qué nomina() no cambia al añadir un nuevo tipo de empleado?

    Porque trabaja con el tipo general Empleado y la ligadura dinámica elige el pago() de cada uno.
